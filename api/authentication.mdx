As rotas B2B (`/api/v1/...` e a maior parte do `/api` de developers) exigem o header:

```
X-API-Key: pk_live_...
```

Não é sessão cookie e **não** é `Authorization: Bearer` nestas rotas.

## Obter a chave

1. Entra em [developers.nzochain.com](https://developers.nzochain.com).
2. Cria um projecto.
3. Gera uma API key e guarda-a — trata-a como segredo.

A app B2C ([app.nzochain.com](https://app.nzochain.com)) **não** usa esta chave: usa ligação de carteira.

## Exemplo

```bash
curl -X POST "https://api.nzochain.com/api/v1/wallets/risk?lang=pt" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: pk_live_SUA_CHAVE" \
  -d '{"wallet":"0x742d35Cc6634C0532925a3b8D4C9B5e55d7b1234","network":"ethereum"}'
```

```javascript
const res = await fetch('https://api.nzochain.com/api/v1/wallets/risk?lang=en', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': process.env.NZOCHAIN_API_KEY,
  },
  body: JSON.stringify({ wallet: '0x...', network: 'ethereum' }),
});
const { success, data } = await res.json();
```

## Erros de auth

| HTTP | Significado |
|---|---|
| 401 | `X-API-Key` em falta, inválida ou revogada |

403 de **plano** (`PLAN_UPGRADE_REQUIRED`, `SIMULATION_QUOTA`) são outra coisa — ver [erros](/api/errors).

## Boas práticas

- Só no servidor. Nunca no JavaScript do browser de um dApp público.
- Variável de ambiente. Roda chaves se vazarem.
- Uma chave por ambiente (dev / prod).
